The update overlay replaces the old dialog-only update flow with an in-app BrowserView.

## Behavior

When an update check starts, Kawaikara opens an update BrowserView over the main window. The overlay uses the same bounds as the menu overlay, so it covers the current app surface consistently.

The overlay shows:

- checking state
- update available state
- download progress
- update downloaded state
- cancelled state
- error state

During an active update operation, all keyboard input is locked by the main process. The app still allows mouse interaction with the update overlay buttons.

## Cancellation

Downloads are started with an `electron-updater` `CancellationToken`. The Cancel button calls the preload update API, then the main process cancels the token and returns the overlay to a cancellable state.

## Renderer API

The update renderer uses `window.KAWAI_API.update`:

- `status()`
- `notify_status(callback)`
- `start_download()`
- `cancel()`
- `install()`
- `close()`
