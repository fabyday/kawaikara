# ロギングと診断

Kawaikara は Main プロセスの起動時に、単一の `electron-log` パイプラインを
初期化します。既存の `console.debug/info/warn/error` 呼び出しはこのパイプラインへ
転送されるため、各サブシステムが個別にファイル出力を設定しなくても Manager と
Built-in Plugin のログが保存されます。`LoggingManager` は初期化、実行中のログ
レベル変更、Renderer の接続、診断ディレクトリへのアクセス、セッション終了を
管理します。これはアプリケーションの Manager コンテナに登録され、スコープ付き
Logger や Renderer ログの収集を必要とする Consumer に注入されます。安定した
サブシステム Label が必要な新しいコードでは、
`src/Main/Manager/LoggingManager.ts` の `logging.createLogger(scope)` を使用できます。

## 出力と保存

現在のログファイルは `UserRoot/KawaiData/logs/kawaikara.log` です。Electron 自身の
`userData` と `sessionData` パスは `UserRoot/Electron` を参照するため、実行時 Cache
は Kawaikara が管理する設定、Library の状態、診断情報から分離されます。ログが
5 MiB に達すると、`electron-log` が直前のファイルを Archive する方式でローテーション
します。開発ビルドでは `debug` 以上、Package ビルドでは `info` 以上を記録します。
実行時の `KAWAIKARA_LOG_LEVEL` には `error`、`warn`、`info`、`verbose`、`debug`、
`silly` のいずれかを指定できます。

プロセスを起動するたびに、ランダムな Session ID、App/Runtime バージョン、
Release Channel、Platform、Architecture、Renderer Mode、起動完了、正常終了を
記録します。環境設定 > アプリ情報 > 診断ログから、ログを格納するフォルダを開けます。

## 収集する障害

- 未処理の Main プロセスエラーと Promise Rejection。
- Electron の Child/Renderer プロセス終了、Preload の失敗、Navigation Load の失敗。
- アプリが所有する Viewer、Overlay、Video、PiP 画面の Console 出力と、応答なし/
  応答復帰の遷移。
- 既存の Manager、Site、Updater、Native Video、HLS のエラーメッセージ。

リモート Site には Logging Bridge を提供しません。対象 Site の JavaScript Console
出力はログファイルへコピーされませんが、Electron レベルの Load および Process
エラーは引き続き記録されます。

## プライバシー境界

出力前に Logger は、一般的な Authorization、Cookie、Password、API Key、
Credential、Token の Field を再帰的にマスクします。HTTP(S) URL の Credential、
Query、Fragment も削除します。ログはローカルにのみ保存され、アプリケーションから
アップロードされることはありません。それでも Contributor は、Media の内容、
Cookie Jar、Request Body、アカウント情報をログに記録しないようにしてください。
