# ブランチとリリースチャンネル

Kawaikara では、ソースブランチ、リリースチャンネル、ドキュメントのプレビューを区別します。バージョン 3.0 の開発ブランチ名は `dev` です。

[English](../../1.BranchesAndChannels.md) · [한국어](../ko/1.BranchesAndChannels.md)

## ソースブランチ

### `main`

`main` は安定版のソースラインです。現在公開されている 2.x アプリケーションと Stable リリース用の自動化を含みます。Stable ドキュメントは任意の作業ツリーではなく、`v2.3.1` のような変更不可能なリリースタグから生成します。

### `dev`

`dev` はバージョン 3.0 の開発ラインです。新しいアプリケーション設計、Site API の変更、Built-in Site Provider、未公開の修正はこのブランチで開発します。Staging と Nightly は `dev` に含まれる特定のコミットを選択します。

ドキュメントでは「`dev` ブランチ」または「バージョン 3.0 開発」と表現します。

## リリースチャンネル

| チャンネル | ソース | バージョン形式 | 目的 |
| --- | --- | --- | --- |
| Stable | 通常は `main` のレビュー済みリリースタグ | `3.0.0` | 一般ユーザー向けリリース |
| Staging | `dev` から手動で選択したコミット | `3.0.0-staging.N` | 手動のプレリリース検証 |
| Nightly | `dev` から自動選択した固定コミット | `3.0.0-nightly.N` | 頻繁な統合ビルド |

Stable は `latest` 更新チャンネルを使用します。Staging と Nightly は別々の更新チャンネル、アプリ ID、リリースリポジトリ、プレリリース版を使用するため、独立してインストールおよび更新できます。

## 公開とドキュメントプレビューの違い

ローカルドキュメントサイトに `dev preview` または `staging` パスが表示されても、Staging アプリケーションが公開されたことにはなりません。リリースワークフローを実行する前でも、現在の `dev` 作業ツリーをローカルで文書化できます。

パッケージングワークフローが完了し、対象チャンネルのリリースリポジトリにリリースが作成された時点で公開済みになります。それ以前の `working-tree` ドキュメントは、予定チャンネルを確認するローカル開発プレビューです。

- `sourceRef: vX.Y.Z`: 変更不可能なタグから生成されたドキュメント
- `sourceRef: working-tree`: 現在のローカル `dev` 作業ツリーから生成された開発プレビュー
- 公開 Staging / Nightly ドキュメント: リリースワークフローが記録した正確なソースコミットから生成

## 昇格手順

1. バージョン 3.0 の変更を `dev` で開発してレビューします。
2. Nightly ワークフローが有効な場合は継続的な統合確認に使用します。
3. リリースレベルの検証が必要なとき、選択した `dev` コミットから Staging を手動公開します。
4. 互換性、パッケージング、更新、移行の確認を通過したコミットだけを Stable バージョンタグへ昇格します。
5. 公開ドキュメントは、公開アプリと同じ固定コミットまたはタグから再生成します。
