# 로깅과 진단

Kawaikara는 Main 프로세스가 시작될 때 하나의 `electron-log` 파이프라인을
초기화한다. 기존 `console.debug/info/warn/error` 호출은 이 파이프라인으로
전달되므로, 각 하위 시스템이 별도의 파일 전송 방식을 설정하지 않아도 Manager와
Built-in Plugin의 로그가 파일에 저장된다. `LoggingManager`는 초기화, 런타임 로그
레벨 변경, Renderer 연결, 진단 디렉터리 접근과 세션 종료를 담당한다. 애플리케이션
Manager 컨테이너에 등록되며, 범위가 지정된 Logger나 Renderer 로그 수집이 필요한
Consumer에 주입된다. 안정적인 하위 시스템 Label이 필요할 때 새 코드는
`src/Main/Manager/LoggingManager.ts`의 `logging.createLogger(scope)`를 사용할 수
있다.

## 출력과 보존

현재 로그 파일은 `UserRoot/KawaiData/logs/kawaikara.log`이다. Electron 자체의
`userData`와 `sessionData` 경로는 `UserRoot/Electron`을 가리키므로 런타임 Cache는
Kawaikara가 관리하는 설정, Library 상태와 진단 정보에서 분리된다. 로그 파일이
5 MiB에 도달하면 `electron-log`가 이전 파일을 Archive하는 방식으로 순환한다.
개발 빌드는 `debug` 이상을, Package 빌드는 `info` 이상을 기록한다. 런타임
`KAWAIKARA_LOG_LEVEL` 값으로 `error`, `warn`, `info`, `verbose`, `debug`, `silly`
중 하나를 선택할 수 있다.

프로세스를 시작할 때마다 임의의 Session ID, App/Runtime 버전, Release Channel,
Platform, Architecture, Renderer Mode, 시작 완료와 정상 종료 여부를 기록한다.
환경설정 > 앱 정보 > 진단 로그에서 로그가 들어 있는 폴더를 열 수 있다.

## 수집하는 오류

- 처리되지 않은 Main 프로세스 오류와 Promise Rejection.
- Electron Child/Renderer 프로세스 종료, Preload 실패와 Navigation Load 실패.
- 앱이 소유한 Viewer, Overlay, Video, PiP 화면의 Console 출력과 응답 없음/응답
  복구 전환.
- 기존 Manager, Site, Updater, Native Video와 HLS 오류 메시지.

원격 Site에는 Logging Bridge를 제공하지 않는다. 해당 Site의 JavaScript Console
출력은 로그 파일에 복사되지 않지만, Electron 수준의 Load 및 Process 오류는 계속
기록된다.

## 개인정보 보호 경계

전송 전에 Logger는 일반적인 Authorization, Cookie, Password, API Key,
Credential과 Token Field를 재귀적으로 가린다. HTTP(S) URL의 Credential, Query와
Fragment도 제거한다. 로그는 로컬에만 남으며 애플리케이션이 업로드하지 않는다.
그렇더라도 Contributor는 Media 내용, Cookie Jar, Request Body 또는 계정 정보를
로그로 남기지 않아야 한다.
