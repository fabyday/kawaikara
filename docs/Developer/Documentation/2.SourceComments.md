# Source Comment Contracts

Canonical source comments use English TSDoc so editor help and generated TypeDoc
reference share the same contract. Localized reference prose follows the
[documentation export and localization rules](./1.ExportAndLocalization.md).

## What needs a detailed contract

Document exported feature entry points and methods with meaningful lifecycle,
permission, mutation or failure behavior. Private functions also need this detail
when an incorrect call can break an invariant. Small self-explanatory helpers can
keep short summaries; comment length is not the goal.

For a significant function or method, describe:

- Purpose: what the caller achieves, rather than restating the symbol name.
- `@param`: each argument's meaning, units, accepted range, optional/default
  behavior and ownership. Explain callbacks and when they run.
- `@returns`: the result, absence/fallback meanings and what asynchronous completion
  guarantees. For a returned disposer, specify who calls it and whether it is idempotent.
- `@throws`: validation failures and propagated errors, including whether work or
  mutations may already have happened when the function fails.
- `@remarks`: ordering, side effects, permissions, shared references, serialization,
  concurrency and cleanup responsibilities that are not expressed by the type.
- `@example`: add a small valid call only when usage or ordering is otherwise unclear.

Do not repeat TypeScript parameter types inside comments. Use actual parameter
names in tags, and update the comment in the same change as the implementation.
Avoid placeholder prose such as “Performs the operation” or “The value”.

## Review and generation

`pnpm docs:source:check` currently checks that declarations have comments. It does
not establish that a comment is accurate or that parameter descriptions are complete.
Review the contract against the implementation, especially exception paths and
shared mutable state. Do not run the auto-comment writer as a substitute for this review.

`pnpm docs:source` generates the reference after that check. Do not manually edit
its generated output to correct a source contract; update the TSDoc instead.
