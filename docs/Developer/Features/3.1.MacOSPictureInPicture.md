# macOS Picture in Picture presentation

This document describes the native window presentation used by both Provider
PiP and internal Video PiP. Media ownership, view transfer and Provider policy
are described in [Unified Picture in Picture](3.PictureInPicture.md).

## Responsibilities

| Component | Responsibility |
| --- | --- |
| `src/Main/Platform/Darwin/Presentation.ts` | Accessory/Dock lifecycle, Electron window level, all-workspaces configuration and inactive presentation |
| `src/Main/Platform/Darwin/WindowSpaces.ts` | Lazily load the Node-API bridge and pass the live native window handle |
| `native/darwin/window-spaces/MacOSWindowSpaces.mm` | Resolve the handle, own native notification subscriptions, reapply Space policy and cancel stale callbacks |
| `native/darwin/window-spaces/PiPExitRecoveryPolicy.h` | Classify display/window geometry and consume fullscreen transition edges |
| `native/darwin/window-spaces/PiPExitRecovery.h` | Read WindowServer metadata and perform the nonactivating recovery operation |
| `scripts/build-native.cjs` | Build the universal arm64/x86_64 add-on with AppKit and CoreGraphics |

Managers do not classify external windows. The native observer owns one recovery
state per PiP window; the decision policy is independent of AppKit calls.

## Entering PiP and joining fullscreen Spaces

1. Enter `accessory` activation policy and hide the Dock icon once per PiP
   session. This avoids repeatedly transforming the application during playback.
2. Set `screen-saver` always-on-top level and call
   `setVisibleOnAllWorkspaces(true, { visibleOnFullScreen: true,
   skipTransformProcessType: true })`.
3. Resolve Electron's native handle to its `NSWindow` through the Node-API add-on.
4. Remove `MoveToActiveSpace`, `FullScreenPrimary` and `FullScreenNone` before
   applying `CanJoinAllSpaces` and `FullScreenAuxiliary`. On macOS 13+, select
   `CanJoinAllApplications`, removing the mutually exclusive primary/auxiliary
   application grouping flags. Set `NSScreenSaverWindowLevel`.
5. Show with `showInactive()` and `moveTop()`. The existing media view remains in
   the PiP host; no new page, media renderer or decoder is created for a Space change.

These flags allow PiP to participate in another application's fullscreen Space.
They do not detect Game Mode or guarantee that the compositor has presented the
window after every transition.

## Why an additional recovery operation is necessary

In the observed failure, leaving an external fullscreen Space could leave PiP
invisible but clickable. `visible`, `onActiveSpace` and `occlusionVisible` could
all report true. Reapplying the window policy or ordering an already-visible
window to the front did not reliably restore it. Repeating the occlusion
notification also did not resolve the observed case.

The selected workaround removes the existing native window from the display
order and reinserts it without activating Kawaikara. It is a presentation
workaround; the precise AppKit/WindowServer/Electron cause has not been isolated.
It must not be applied to every Space change: doing so makes successful entries
into fullscreen flash unnecessarily.

## Classifying the PiP display

On a workspace or application activation notification, the bridge obtains the
display containing PiP from `window.screen` and uses `CGDisplayBounds` for its
complete bounds. It queries `CGWindowListCopyWindowInfo` for on-screen windows,
excluding desktop elements, the current process, nonzero window layers and
fully transparent windows.

`ClassifyDisplay(display, windows)` consumes these candidates in front-to-back
order. It ignores candidates whose intersection with the PiP display is less
than 100 points wide or high. The first substantial candidate is classified as:

- **Fullscreen:** its origin and size match the complete display bounds within
  two points on each coordinate/dimension.
- **Normal:** it intersects the display substantially but does not match those bounds.
- **Unknown:** no qualifying candidate is available.

The snapshot includes `kCGWindowNumber`, not just a PID or bundle ID. Two
fullscreen windows belonging to the same app must remain distinguishable.
No window titles, pixel captures, accessibility tree queries or keyboard input
are needed for this decision.

This is a geometry heuristic. A borderless display-sized window qualifies;
Game Mode state and private Space IDs are not queried. Work-area maximization,
small overlays, split-screen layouts and unusual window layers may classify
differently from a user's description of “fullscreen”.

## Transition rules and multiple monitors

`ExitRecoveryState::Observe(displayId, snapshot)` stores the previous known
coverage and window ID for the PiP display and returns whether to recover.

| Previous state | Current state on the same display | Recover |
| --- | --- | --- |
| Normal | Fullscreen A | No |
| Fullscreen A | Normal | Once |
| Fullscreen A | Fullscreen B, with a different known window ID | Once |
| Fullscreen A | Fullscreen A | No |
| Normal | Another normal window | No |
| Any | Unknown metadata | No; retain the previous known state |
| Any | PiP moves to a different display ID | No; establish a new baseline |

Missing fullscreen window identity does not prove a transition and does not
erase a previously known fullscreen ID. Repeated notifications for the same
destination do not repeat the recovery.

Global application focus is insufficient for multiple monitors. If monitor 1
still shows fullscreen A while the user selects an app on monitor 2, monitor 1
remains armed. Only a change in the qualifying window on the PiP display
triggers recovery. A monitor removal/fallback that changes the PiP display ID
resets the baseline rather than treating the topology change as a fullscreen exit.

## Scheduling and recovery

The observer listens to `NSWorkspaceActiveSpaceDidChangeNotification` and
`NSWorkspaceDidActivateApplicationNotification`. Each event increments a
generation and reapplies the window policy immediately. Classification first
runs asynchronously on the main queue, after the current event-loop turn,
without a fixed 250 ms delay. Existing bounded follow-ups at 250 ms and 1 second
reapply policy and inspect metadata again if the transition has not settled.
Only callbacks for the current generation and active observer may run.
There is no repeating polling timer.

For a qualifying edge, `observeWindow:` performs the following on the AppKit
main thread:

1. Ignore absent, hidden or minimized PiP windows.
2. Consume the edge. If PiP is key or Kawaikara is active, skip ordering so an
   ongoing interaction is not interrupted.
3. Save `animationBehavior`, temporarily set it to `None`, and use an
   `NSAnimationContext` with zero duration and implicit animation disabled.
4. Call `orderOut:nil` followed immediately by `orderFrontRegardless` within
   that group. Do not activate the application or make the window key.
5. Restore the previous animation behavior and reentrancy guard in `@finally`.

Grouping reduces visible transition artifacts in the tested environment; it
does not promise atomic compositor output on every macOS/device combination.
No deprecated screen-update suspension, focus roundtrip, synthetic occlusion
notification, periodic probe or diagnostic logger is part of the runtime path.

## Lifetime, build and validation

The observer is associated with the native PiP window and holds that window
weakly. Explicit PiP exit and `NSWindowWillCloseNotification` remove observers
and invalidate queued callbacks. Occlusion/hide notifications are not teardown
signals: macOS may emit them during normal Space changes. Exit restores the
previous collection behavior, clears fullscreen membership, restores `regular`
activation and Dock visibility, and then presents the normal Viewer.

`pnpm build:native` builds the normal bridge; no experiment environment variables
or development-only flags are required. Packaging copies it into
`resources/native`. If loading fails, Electron's public all-workspaces behavior
remains the existing best-effort fallback.

The bridge's existing `getWindowSpaceState(handle)` export is read-only. It
reports native visibility, active-Space membership, occlusion, watcher lifetime,
refresh count and application activation; it does not trigger recovery. The
existing real-addon probe can be run with
`pnpm exec electron tests/Electron/pip-macos-spaces.electron.cjs` after building
the native bridge. Its state assertions do not replace a visual Space test.

Manual validation confirmed recovery for fullscreen-to-normal and
fullscreen-to-fullscreen transitions in the user's macOS/NTE environment. Policy
checks covered monitor isolation, repeated events, unknown metadata and display
changes. These checks do not certify all games, macOS releases or playback backends.

Recheck actual visibility, flicker, keyboard focus and playback in both
directions, with two fullscreen windows (including the same app), and with a
detour through monitor 2. Also verify PiP close/return, dragging to another
monitor and display removal. Native visibility flags or a window-only capture
are insufficient evidence that PiP is visible on the user's active desktop.

## Retained investigation results and cleanup

The one-off `pip-exit-recovery.cpp` harness and local `tmp/pip-*` experiments
are not shipped or required by the build. Their policy cases are recorded here
so temporary native binaries, instrumented snapshots and event logs can be removed:

| Transition or input | Expected policy |
| --- | --- |
| Normal window → fullscreen A | Record A; do not cycle PiP |
| Fullscreen A → normal window on the PiP display | Recover once |
| Fullscreen A → fullscreen B → A | Recover once per distinct window ID, even within the same app |
| Focus moves to monitor 2 while monitor 1 retains fullscreen A | Retain monitor 1's baseline; no recovery |
| Duplicate notifications, missing windows or unknown fullscreen ID | Do not repeat recovery or erase the known fullscreen identity |
| PiP moves to another display or its display disappears | Reset the display baseline |
| Negative display origins, maximized work-area windows, tiny transient windows, slight cross-display overlap | Classify against the PiP display's actual bounds; do not infer fullscreen from another display |

Repeat visual testing with the normal native bridge and actual user Space
transitions. Accessibility queries and clicking an invisible PiP changed the
observed failure during investigation, so they must not be treated as passive
proof of visibility. High-frequency diagnostic polling caused severe disruption
in the test environment; no periodic diagnostic probe is required or enabled
by this implementation. Separate a window-membership regression from playback
stutter by comparing the same content, build and Game Mode state.

Runtime profiles and `tmp/development-connections` are not disposable probe
output: the latter contains durable pairing/revocation records. Cleanup must
not remove those directories together with investigation artifacts.
